# OPERATIONAL MANUAL: Autonomous Execution Safety

## 1. EXECUTIVE COMPRESSION

**Problem:** Autonomous coding agents (like Claude Code, Cursor, or LangGraph loops) are typically granted raw terminal access to the host machine to execute tests, install packages, and build artifacts. This creates an unquantifiable vulnerability. If an agent hallucinates a destructive shell command (e.g., `rm -rf /` or `curl <malicious_payload> | bash`), it executes with the full privileges of the host user. 

**Consequence:** "rm -rf Class Failures." A hallucinating agent can delete entire repositories, expose environment variables, or execute supply-chain attacks autonomously. The blast radius of an unconstrained terminal session is total system compromise.

**Remediation:** Implement an **Execution Gating Layer**. All terminal commands generated by the LLM must be intercepted by a Runtime Permission Validator that compares the command against a strict, deterministic whitelist before it is passed to the host OS.

---

## 2. FAILURE TAXONOMY

### Observable Symptoms
- **Unsafe Shell Execution**: Agents attempting to run destructive file-system commands (`rm`, `chmod -R 777`) instead of using safer APIs.
- **Autonomous Infrastructure Corruption**: An agent tasked with cleaning up a `build` folder accidentally deletes the `src` folder due to a wildcard hallucination (`rm -rf *`).
- **Data Exfiltration**: An agent executes an unauthorized `curl` or `wget` command to an external IP, potentially leaking `.env` secrets.

### Root Causes
- **Direct Terminal Access**: Allowing the LLM to write directly to a `bash` or `zsh` session without middleware validation.
- **Governance Theater**: Relying on system prompts (e.g., "Do not run destructive commands") to stop probabilistic models from making errors.

### Economic Impact
- **Total System Compromise**: Rebuilding a corrupted host environment or recovering a deleted database costs significant engineering hours.
- **Security Breach Liability**: Leaking customer data or proprietary source code due to unconstrained execution vectors.

---

## 3. TELEMETRY SIGNALS

Monitor your orchestration dashboards for the following critical indicators:
- **`command_rejection_rate`**: Spikes indicate the agent is hallucinating unsafe commands or is trapped in an environment it doesn't understand.
- **`network_egress_attempts`**: Any unauthorized `curl` or `wget` attempt must trigger an immediate Sev-1 alert.
- **`banned_command_invocations`**: Tracks exact hits against the `execution-safety-policy.yaml` denylist.

---

## 4. GOVERNANCE ARCHITECTURE

This system relies on three core operational mechanisms:

1. **Execution Safety Policy (`execution-safety-policy.yaml`)**: Declares the absolute whitelist of allowed bash commands and the hard denylist of catastrophic commands.
2. **Runtime Permission Validator (`runtime-permission-validator.ts`)**: Middleware that intercepts the string payload intended for the terminal, parses it, and blocks execution if it violates the safety policy.
3. **Autonomous Boundary Engine (`autonomous-boundary-engine.ts`)**: Sandboxing logic that ensures even allowed commands are executed within a restricted filesystem path (e.g., `cwd` bounds).

---

## 5. DEPLOYMENT INSTRUCTIONS

1. **Configure the Whitelist**: Edit `execution-safety-policy.yaml` to define exactly what your agent is allowed to do (e.g., `npm run test`, `git status`).
2. **Deploy the Interceptor**: Never give your agent direct access to `execSync` or a raw PTY. Route all commands through `runtime-permission-validator.ts`.
3. **Enforce Boundaries**: Ensure the `AutonomousBoundaryEngine` is initialized with the absolute path of the target repository, preventing directory traversal (`cd ../../../`).

---

## 6. EXOGRAM MAPPING

**Exogram enforces deterministic runtime governance.**

By piping the `RuntimePermissionValidator` into the Exogram Control Plane, SecOps receives a real-time feed of all intercepted commands. Exogram categorizes intercepted commands by risk level. If a catastrophic command (`rm -rf`) is intercepted, Exogram automatically revokes the agent's LLM API keys globally, quarantining the threat.
