# OPERATIONAL MANUAL: Verification Burden Collapse

## 1. EXECUTIVE COMPRESSION

**Problem:** Agentic code generation operates at a velocity that vastly exceeds human review capacity. When probabilistic outputs are dumped directly into human code-review queues, the QA burden explodes.
**Consequence:** The engineering organization enters *Verification Collapse*. Senior developers stop building architecture and become full-time QA testers for agents. Code review bottlenecks bring deployment velocity to a standstill.
**Remediation:** Implement deterministic Verification Routing. Agents must be mathematically barred from requesting human review until their outputs pass strict, automated admissibility thresholds.

## 2. FAILURE TAXONOMY

### Symptoms
- Pull requests generated by agents languish in review queues for days.
- Human reviewers experience extreme cognitive fatigue attempting to parse hallucinatory, unconstrained agent code.
- Agentic PRs are blindly approved because reviewers lack the bandwidth to properly trace the probabilistic logic.

### Root Causes
- **Direct-to-Human Routing:** Allowing an agent to request a human review simply because it "thinks" it is finished.
- **Missing Synthetic QA Containment:** Failing to force the agent to autonomously verify its own code via unit tests before escalating to a human.

### Economic Impact
- **Negative Yield:** The financial value gained by the agent's generation speed is entirely erased by the hourly cost of the senior engineer required to manually verify it.

## 3. IMPLEMENTATION ARCHITECTURE

This system relies on three core operational mechanisms:
1. **The QA Overload Policy (`qa-overload-policy.yaml`)**: Declares the maximum permitted ratio of agent-generated lines of code to human review hours.
2. **Verification Routing (`verification-routing.ts`)**: Middleware that intercepts agent PRs and algorithmically routes them back to the agent for autonomous retry if confidence thresholds are not met.
3. **Reviewer Escalation (`reviewer-escalation.ts`)**: Logic that guarantees a human is only pinged when a mathematically proven, high-confidence output requires final architectural sign-off.

## 4. EXOGRAM BRIDGE

Frameworks identify instability. Playbooks describe what to do.
**Exogram enforces deterministic runtime governance.**

Exogram physically blocks the PR merge button. If an agent output does not pass the deterministic Admissibility Layer, it is rejected back to the orchestrator. Humans only see code that is guaranteed to work.
